# Contributing

[Repository](README.md) / Contributing

**Bring an inspectable contribution:** a source, a methodological criticism, a reproducible failure, or a proposed improvement with evidence.

| Contribution | Include | Review route |
| :--- | :--- | :--- |
| Candidate event | Stable identifiers, event scope, discovery provenance, source families, access and rights status, primary retrieval plan | [Pilot intake](research/pilot/README.md) |
| Methods criticism | Affected construct, counterexample, competing explanation, proposed decision rule | [Codebook](docs/methods/CODEBOOK.md) and [comparative design](research/COMPARATIVE_PILOT_DESIGN.md) |
| Literature correction | Exact work and version, inspected sections, demonstrated overlap or unresolved access | [Novelty review](research/NOVELTY_REVIEW.md) |
| Software or schema change | Reproducer, affected IDs, methodological effect, validation results, migration implications | [Reproducibility guide](docs/reference/REPRODUCIBILITY.md) |
| Evidence correction | Affected IDs, asserted error, supporting evidence, privacy concerns | [Ethics and corrections](docs/policies/ETHICS_AND_CORRECTIONS.md) |

Start with the [Charter](RESEARCH_CHARTER.md), [Agenda](RESEARCH_AGENDA.md), and [source policy](docs/policies/SOURCE_POLICY.md). Keep sparse candidates in the availability record. Disclose material AI assistance and reviewer exposure.

## Before submitting a change

1. Preserve sealed initial judgments; use new correction or adjudication objects.
2. Keep source text out of the repository unless a source-specific rights decision permits it.
3. Run the relevant checks and state what they establish.
4. Identify any effect on interpretation, comparability, or downstream records.

Confirmatory labels and reviewer attestations require the actual eligible people. Passing software tests is insufficient for scientific release. The repository currently contains synthetic development records and an unrated reconnaissance note.

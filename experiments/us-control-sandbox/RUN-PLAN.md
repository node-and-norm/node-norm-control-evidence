# Prospective run plan, development candidate 0.1

2 October 2026. Not frozen for a new evaluation cohort. No new scenario families, independent key, blinded assessment or model run is authorized by the existence of this file.

## Fixed for procedure development

- Unit: one supplied packet, one record-level objective, one terminal observation scope.
- Procedures: `paired-record-procedures/0.1`, checklist and full trace. Shared validation and extraction; identical admissible inputs.
- Response vocabulary and arithmetic: technical-evidence-evaluation/0.1. Existing appendix and method-admissibility boundaries remain active.
- Initial demonstration: seven declared existing public packets. No hidden key or accuracy comparison; retain all responses and failed attempts.
- Failure policy: reject malformed or unsupported envelopes. Preserve planned missingness as unresolved. Retain failed attempts and never overwrite output directories.

## Required before new cases

| Item | Decision still needed |
| --- | --- |
| Comparison claim | Decide whether complete traces improve inspectable coverage enough to justify their size. Do not claim superior label accuracy for identical rules. |
| Trace-quality measure | Fix what counts as an omitted material blocker, unsupported reason, incorrect locator and excess output burden; require rationale review beyond self-recomputation. |
| Cohort and families | Predeclare family boundaries, case counts, inclusion/exclusion criteria, packet-generation policy and known dependencies. Avoid turning renamed development cases into a holdout. |
| Evidence-sufficiency key | Separate from execution outcomes; preserve each unit's objective, locators, rationale, key authorship and exposure. Author-generated keys cannot establish independent validity. |
| Access | Keep evaluator inputs separate from execution outcomes and reference keys. In a solo study, disclose author exposure; do not claim independent blinding. |
| Acceptance and failures | State claim-specific criteria before running; account for exclusions, invalid attempts and ambiguous rationales. A software pass does not supply a research threshold. |
| Versions | Record the committed plan, procedure and packet policy before case creation; record key and input hashes before evaluator execution. |

The next implementation should remain a researcher-led technical study without participants. A future model adapter requires a separate versioned plan for model identity, prompts, repeated trials, costs, data rights and information access. Adding Hugging Face, LangChain or a hosted model solely as a visibility signal would not answer the current comparison question.

Original TAE and HIT studies continue separately. Authentic human-control findings still require the applicable unit, authority, evidence and review required by their contracts.

# Response validity and reference review

The comparison does not justify another instruction revision yet. Fourteen response failures reduced coverage, and the action reference for pair 12 relies on an unstated request-to-job relationship. These require separate follow-up designs. The primary result remains 11 A-only versus 11 B-only matches among 96 eligible judgments.

This is a post-output, AI-assisted diagnostic of public synthetic cases with access to the reference. It provides no independent adjudication, empirical control assessment or new live inference. Original responses, exclusions, labels and scores remain unchanged.

## Why the responses were excluded

The [reproducible register](VALIDITY-REVIEW.json), generated by [review_validity.py](review_validity.py), checks every response against its recorded hash and inspects all four probability distributions in each response. Each of the 14 invalid responses has exactly one distribution totaling approximately 0.99. The shortfall is about 0.01, well beyond the frozen absolute tolerance of 0.00001; ordinary floating-point summation differences do not explain these rejections. The provider mechanism producing the shortfall is unknown.

All selected choices in these responses are maxima of their supplied distributions. This observation does not make those distributions valid. Validation rejects the complete four-answer response when any answer fails, so 14 failing distributions excluded 56 judgments, including 42 distributions that met the sum tolerance. A had six rejected responses and B eight, spread evenly across their two passes.

The current experiment uses response-level acceptance. Changing to answer-level acceptance or normalizing sums would change the analysis contract after observing results. Such an analysis could be useful as explicitly labeled sensitivity work, with original exclusions retained, but no such scores are reported here. Invalidity is distinct from an incorrect substantive judgment and from insufficient documentary evidence.

## Where the proposed reference needs work

Pair 12 supplies: “The console issued R.” It never explicitly identifies R as a stop request for J. The scope names the intended objective, but the frozen instruction says scope is not observed evidence. The proposed action label `yes` therefore depends on implicit linkage.

Only four of eight pair-12 action judgments are valid: three are `not_reported` and one is `not_observable`; all disagree with `yes`. This does not establish that the model alternatives are correct. In particular, an account-record restriction does not by itself restrict evidence about issuance. The four excluded judgments remain excluded.

Pair 02 also abbreviates R, but its evidence connects receipt to J, and its B variant says R cancelled J. Its context is stronger than pair 12. A future packet review must distinguish those contexts rather than apply a blanket replacement label. The prior [disagreement review](../execution-v2/DISAGREEMENT-REVIEW.md) also identifies the unresolved `unknown` versus `not_reported` boundary in readable ambiguous records.

## Next step and its stopping point

Prepare a separate packet-linkage diagnostic before another live run. Preserve the original pair-12 packets as the ambiguous condition. In a new explicit condition, replace only the issuance statement with “The console issued stop request R targeting fee job J.” Preserve every later-stage statement, scope, question and model setting. The action reference for the explicit condition can then be justified from that statement; the ambiguous condition should retain an unresolved reference status in the new diagnostic. Keep its historical `yes` label in the original archive.

Document the prospective comparison, exact edits, admissible conclusions and response-validity rule before dispatch. Use the frozen shared instruction package so packet linkage is the intended changed factor. This would test behavior on a clarified packet, with no claim of improved general accuracy. Additional live execution should follow that specification, not occur as part of this review.

For response validity, retain the strict rule and seek a documented explanation or an independently specified sensitivity analysis before changing it. No provider fault mechanism, rounding explanation or preferred repair is established by this archive.

TAE and HIT remain unchanged. These findings concern a development classifier's response format and the evidence supplied to it; they do not measure real human intervention or validate the core methods.

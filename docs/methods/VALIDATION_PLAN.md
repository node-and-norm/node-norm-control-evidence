# Validation plan

[Repository](../../README.md) / [Documentation](../README.md)

## Software integrity

Software validation checks schemas, typed references, source dependence, packet scope, immutable rating identifiers, temporal syntax, synthetic separation, and export determinism. Mutation tests must reject plausible research-integrity failures, including evidence from another event, AI labels promoted to authoritative human ratings, derivative evidence marked independent, and inconsistent adjudication inputs.

## Content, reliability, and convergence

Content validation requires external review of construct coverage against the literature and control mechanisms. Record reviewer disagreements and revisions. Inter-rater reliability tests application consistency, not truth. Convergent comparison with TAE or HIT requires independently coded overlapping cases and explicit source-dependence accounting. Their labels cannot be imported as criterion truth.

## Discriminant checks

Discriminant checks should include formal authority with no usable override, an override attempt with unknown propagation, an operating detector with failed escalation, and successful prevention without an alarm. The synthetic fixture exercises software semantics only; it supplies no empirical validity evidence.

## Criterion validity

Criterion validity requires known control states in controlled or prospective settings. Specify manipulation, observation instrumentation, ground-truth custody, blinding, and failure criteria before data collection. Historical incident reconstruction cannot close this gate.

## Research release review

Release reviewers must examine unresolved findings, privacy, rights, independence, duplicate families, reproducibility, and deviations. Software passes alone cannot open an empirical release. The first implementation intentionally permits only synthetic development exports.
